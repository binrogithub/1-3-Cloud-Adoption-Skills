## Why

Two gaps identified in a survey of open-source projects worth adding to ai-dlc, both scoped to items the survey explicitly flagged as complementary rather than duplicating any existing role (jiuwenswarm/openjiuwen for the agent runtime, openspec for spec management, understand-anything for codegraph, opendesign for UI design, the review axes for adversarial LLM critique, claude-maas-delegate for offload):

1. Live page verification (clicking, filling forms, walking a full user journey) exists nowhere in ai-dlc today. `render_check()` in `bin/plan.py` hand-rolls an `http.server` + `html.parser` reimplementation of exactly the narrower "did it render, is the DOM non-empty" question, invoked synchronously inside the design dispatch's fact-checking path (`design_facts`) — never dispatched through the plane. Playwright MCP (Microsoft, Apache-2.0) already does this properly via the accessibility tree and is what GitHub Copilot's own coding agent uses for the same purpose.
2. Nothing in ai-dlc measures the pipeline's own aggregate output quality over time. `plan.py review` and `plan.py validate` are both per-change judgments; there is no standing benchmark tracking whether a model/prompt change improved or regressed the pipeline as a whole. Harbor (the official Terminal-Bench 2.0 evaluation harness, `pip install harbor`) is the standard open-source answer.

Both are added as new plane-dispatched roles, following the existing `codegraph` role's architecture exactly — a pinned, digest-verified external tree, a thin conduit skill, and a dispatch function of the fixed `[CLIENT, "chat", prompt, ...]` shape. Neither Playwright MCP nor Harbor is forked or patched; both are installed as unmodified upstream releases, with a `.aidlc-pin.json` digest that a dispatch refuses to proceed against if the pinned tree no longer matches (the technical enforcement of "no changes to upstream").

## What Changes

- **`browser-verify` role**: `scripts/install-browser-verify.sh` installs `@playwright/mcp` (pinned npm version) plus Chromium into `/opt/playwright-mcp` (override via `AI_DLC_PLAYWRIGHT_MCP_ROOT`) and writes `.aidlc-pin.json`. `browser_verify_pin_state()` verifies it (same shape as `understand_anything_pin_state()`). `supervisor/skills/workspace/browser-verify/SKILL.md` is a thin conduit telling a dispatched role how to drive the pinned Playwright MCP against a list of pages and write a structured pass/fail report. `run_browser_verify_session()` dispatches it (same shape as `run_codegraph_session()`). New `plan.py browser-verify --change <id> --repo <repo> --pages <comma-separated>` subcommand wires it together, recording the outcome in `state.json`/`events.jsonl`.
- **`agent-bench` role**: `scripts/install-agent-bench.sh` installs Harbor into an isolated venv under `/opt/agent-bench` (override via `AI_DLC_AGENT_BENCH_ROOT`) and writes `.aidlc-pin.json`. `agent_bench_pin_state()` verifies it. `supervisor/skills/workspace/agent-bench/SKILL.md` is a thin conduit telling a dispatched role how to run Harbor's own dataset and summarize the result. `run_agent_bench_session()` dispatches it. New `plan.py bench [--dataset ...] [--model ...] [--n-concurrent N]` subcommand — takes no `--change`, touches no `.ai-dlc/tasks/` state, writes a signed result (including the pinned tool's version) to `/var/lib/aidlc/bench-history/<timestamp>.json`.
- `render_check()` and its existing caller in `design_facts` are left exactly as they are — this change is purely additive.

## Non-goals

- No modification to Playwright MCP or Harbor source — both are installed as unmodified upstream releases; a pin-digest mismatch refuses the dispatch rather than proceeding against a locally-altered tree.
- The orchestrating `plan.py` process itself never directly executes a Playwright or Harbor binary — the only permitted call shape is the existing `[CLIENT, "chat", ...]` dispatch pattern already used by `run_codegraph_session`/`run_design_session`; this is checked by a new static grep-based collapse gate (no other code path may name these executables).
- `agent-bench` never gates any single change's `delivered` status and never appears in `report.py deliver`'s criteria — it is a standalone diagnostic invoked independently of the per-change task lifecycle.
- No custom benchmark dataset built from ai-dlc's own merged history in this change — Harbor's own public `terminal-bench@2.0` dataset is used as-is; a custom dataset is a distinct future change.
- No replacement of `render_check()`'s existing call site — the new `browser-verify` dispatch path is additive; whether to migrate `design_facts` to it later is an explicit future decision, not assumed here.
- No cost/budget gate of any kind (per `SKILL.md`'s standing prohibition).
