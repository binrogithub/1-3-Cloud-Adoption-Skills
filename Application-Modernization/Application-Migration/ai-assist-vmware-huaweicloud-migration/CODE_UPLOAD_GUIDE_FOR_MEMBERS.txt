代码仓成员上传代码操作指引（适用于本仓库）

一、适用对象
1) 新加入本项目、需要向仓库提交代码的成员。
2) 使用 Git 和代码托管平台（CodeHub/GitLab/GitHub）进行协作的成员。

二、开始前准备
1) 申请仓库权限
   - 请项目管理员将你加入仓库成员，并授予可写权限（Developer/Write 及以上）。
2) 安装 Git
   - Linux/macOS：终端执行 `git --version`，确认已安装。
   - Windows：安装 Git for Windows 后，在 Git Bash 执行 `git --version`。
3) 配置 Git 身份（首次仅需一次）
   - `git config --global user.name "你的姓名或英文名"`
   - `git config --global user.email "你的邮箱"`
4) 配置 SSH Key（推荐）
   - 生成密钥：`ssh-keygen -t ed25519 -C "你的邮箱"`
   - 查看公钥：`cat ~/.ssh/id_ed25519.pub`
   - 将公钥内容添加到代码托管平台的 SSH Key 配置页面。
   - 测试连通：`ssh -T git@codehub.devcloud.ap-southeast-3.huaweicloud.com`

三、首次拉取仓库代码
1) 克隆仓库
   - `git clone git@codehub.devcloud.ap-southeast-3.huaweicloud.com:66a2bc07bd6e47cfbc008ecbac9ec962/ai_assit_migration.git`
2) 进入目录
   - `cd ai_assit_migration`
3) 查看远程地址（确认无误）
   - `git remote -v`

四、日常上传代码标准流程（推荐每次都按此流程）
1) 先同步主分支最新代码
   - `git checkout master`
   - `git pull origin master`
2) 创建并切换到你的功能分支（不要直接在 master 开发）
   - `git checkout -b feature/你的功能名`
   - 示例：`git checkout -b feature/add-migration-retry`
3) 编写/修改代码后检查改动
   - `git status`
   - `git diff`
4) 添加要提交的文件
   - `git add <文件路径>`
   - 或添加全部改动：`git add .`
5) 提交代码
   - `git commit -m "feat(module): 简要说明本次改动"`
   - 示例：`git commit -m "fix(terraform): handle missing source id"`
6) 推送分支到远程仓库
   - 首次推送：`git push -u origin feature/你的功能名`
   - 后续推送：`git push`
7) 在代码托管平台发起合并请求（PR/MR）
   - 源分支：`feature/你的功能名`
   - 目标分支：`master`
   - 填写变更说明、影响范围、测试结果，并指派评审人。

五、提交信息建议格式
1) 推荐格式：`type(scope): summary`
2) 常用 type
   - feat：新功能
   - fix：修复问题
   - docs：文档更新
   - refactor：重构（不改变外部行为）
   - test：测试相关
   - chore：构建或杂项维护

六、常见问题与处理
1) 报错：`Permission denied (publickey)`
   - 原因：SSH Key 未配置或未生效。
   - 处理：重新添加公钥并执行 `ssh -T git@codehub.devcloud.ap-southeast-3.huaweicloud.com` 验证。
2) 报错：`rejected` 或 `non-fast-forward`
   - 原因：远程分支有新提交，本地落后。
   - 处理：
     - `git fetch origin`
     - `git rebase origin/master`（或 `git pull --rebase origin master`）
     - 解决冲突后再 `git push`
3) 报错：`Please tell me who you are`
   - 原因：未配置 Git 用户名/邮箱。
   - 处理：执行第二部分第 3 步命令后重新提交。

七、协作规范（务必遵守）
1) 不要直接 push 到 `master`，统一走分支 + PR/MR 审核流程。
2) 每次提交前先同步 `master`，减少冲突。
3) 一个分支只做一类改动，便于评审和回滚。
4) 代码提交前至少完成一次自测（包括关键命令和核心路径）。

八、最简流程速查（5 条命令）
1) `git checkout master && git pull origin master`
2) `git checkout -b feature/xxx`
3) 修改代码后执行 `git add .`
4) `git commit -m "feat(xxx): your change"`
5) `git push -u origin feature/xxx`，然后在平台发起 PR/MR
