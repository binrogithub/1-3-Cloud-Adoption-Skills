4. Instrucciones de Ejecución

El usuario dio dos instrucciones clave durante la sesión:

"Crear primero los recursos de red y aplicarlos, después hacemos la migración." — Esto llevó a la IA a dividir el Terraform en dos configuraciones separadas (network/ y migration/), aplicando primero la red y luego la migración.

"Cambia la configuración para que apunte a la RDS de HuaweiCloud que ya desplegé." — Después de la migración, el usuario pidió reconfigurar wp-config.php para conectar el WordPress migrado a la RDS de HuaweiCloud.

Qué Tuvo Que Considerar

  • Dependencia de base de datos: El WordPress dependía de un RDS de AWS con endpoint VPC-internal. Tras migrar, sería inalcanzable. El usuario decidió postergar este problema y resolverlo después.
  • Firmware UEFI: El EC2 usaba UEFI. La IA manejó esto automáticamente con el SMS Server Template, pero el usuario debía saber que un approach manual (pre-crear ECS) podría fallar por mismatch UEFI/BIOS.
  • Región SMS vs región target: El servicio SMS no está disponible en la-north-2, solo en ap-southeast-3. El ECS target sí va en la-north-2. El usuario no necesitó decidir esto, pero debía entender la distinción.
  • Solapamiento de CIDR: El VPC de AWS usaba 10.0.0.0/16 y el VPC default de HuaweiCloud usaba 192.168.0.0/16 — sin solapamiento, lo que permitía crear el VPC target con el mismo CIDR que el origen.

Lecciones Clave y Qué Considerar

Estos son los aprendizajes de esta migración que todo usuario debe considerar al usar IA para migrar servidores con SMS.

🔥

Compatibilidad de Firmware (UEFI/BIOS)

La mayoría de clouds modernos (AWS, Azure, GCP) usan UEFI para imágenes Linux recientes. HuaweiCloud puede usar BIOS por defecto. El SMS Server Template approach maneja esto automáticamente seleccionando una imagen compatible. Pre-crear el ECS manualmente puede causar el error SMS.0515 por mismatch de firmware.

🗄️

Dependencias de Base de Datos

Al migrar un servidor de aplicación (como WordPress), la DB probablemente queda inalcanzable desde el nuevo cloud. Identificar estas dependencias antes de migrar (como hizo la IA al decodificar el userData) es crítico. Planificar la migración de DB en paralelo o posteriormente.

🌐

Región API SMS ≠ Región Target

El servicio SMS solo está disponible en regiones específicas (ej: ap-southeast-3). El ECS target puede estar en cualquier región (ej: la-north-2). Siempre usar --cli-region=sms-region para calls de SMS API, pero region = target-region en el provider de Terraform.

🔑

Manejo de Credenciales

La IA nunca debe adivinar credenciales. Siempre preguntar al usuario por AK/SK y SSH keys. En esta sesión, las credenciales estaban en archivos locales del proyecto. Para production, usar secret managers o input interactivo.

📊

Tipo de Migración: File vs Block

MIGRATE_FILE (nivel de archivo): mejor compatibilidad, más lento, funciona para todo Linux. MIGRATE_BLOCK (nivel de bloque): más rápido, pero solo Windows y puede tener issues en Linux. Para Ubuntu, MIGRATE_FILE es la opción segura.

💾

Diferencias de Tamaño de Disco

El disco target debe ser ≥ al origen. Las imágenes de HuaweiCloud pueden tener requisitos mínimos (ej: 10GB) que exceden el disco origen (ej: 8GB). El template approach maneja esto automáticamente. En esta migración, el disco resultante fue de 40GB (vs 8GB origen).

🧹

Post-Migración

Tareas pendientes después de migrar: (1) actualizar hostname con hostnamectl set-hostname, (2) opcionalmente instalar kernel de HuaweiCloud para mejor soporte de drivers, (3) configurar monitoreo CES/HSS, (4) actualizar DNS, (5) cleanup con terraform destroy (el ECS migrado persiste, solo se borra metadata de SMS).

🤖

El Rol de la IA

La IA actuó como orquestador: descubrió ambos entornos automáticamente, identificó la dependencia de DB al decodificar el userData, formuló 4 preguntas críticas al usuario, generó código Terraform correcto, monitoreó la migración por 48 min, verificó el resultado via SSH, y reconfiguró la aplicación. El humano solo tomó decisiones y proporcionó credenciales.
