The Problem

AI agents writing Terraform are blind

Guesses Everything

"Use VPC vpc-12345678 and flavor s6.large.2" — but those don't exist in your account. The AI has no way to discover your actual infrastructure, so it invents values that break at terraform apply.

Terraform Can't Operate

Need to restart a server? Resize a flavor? Create a manual backup? Terraform is declarative — it provisions infrastructure, but it can't perform day-2 operational actions.

The Solution

Three tools, one intelligent workflow

OpenCode

The Orchestrator

The open-source AI coding agent that ties it all together. Speaks MCP natively, asks you questions when choices arise, and orchestrates both discovery and provisioning.

  • First-class MCP support
  • Asks the user when ambiguous
  • Plan & Build modes

HCloud MCP

The Eyes & Hands

90 read-only tools that let the AI see your Huawei Cloud. Plus a CLI escape hatch for operational actions that Terraform can't do — restart, resize, backup, and more.

  • 90 read-only discovery tools
  • 18 cloud services covered
  • CLI escape hatch for operations

Terraform MCP

The Code Writer

Provider and module registry tools that let the AI write correct Terraform code — resource schemas, required parameters, and latest versions from the official registry.

  • Provider docs & schemas
  • Module discovery & details
  • Latest version lookup
How It Thinks

Not a pipeline — a conversation

The agent doesn't follow a script. It starts with Terraform MCP to understand the schema, writes partial code, then iteratively calls HCloud MCP as it discovers missing values — asking you when choices arise.

You: "I need an RDS MySQL database in la-north-2"
💭 "I need to write Terraform for an RDS instance. Let me get the resource schema first."
terraform_get_provider_details(provider_doc_id="...")
→ needs: flavor_ref, storage_type, vpc_id, subnet_id, availability_zone...
💭 "Writing the Terraform with what I know, but I'm missing some values..."
resource "huaweicloud_rds_instance" "mysql" {
  name           = "prod-mysql"
  engine         = "mysql"
  engine_version = "8.0"
  flavor_ref     = "???"    ← need available flavors
  storage_type   = "???"    ← need region-compatible types
  vpc_id         = "???"    ← need to discover VPC
  subnet_id      = "???"    ← need to discover subnet
}
💭 "Schema requires a flavor_ref. What flavors exist for MySQL here?"
hcloud_list_rds_flavors(region="la-north-2", database_name="MySQL")
→ rds.mysql.x1.large.2 (4 vCPU, 16GB) · rds.mysql.x1.xlarge.2 (8 vCPU, 32GB) · rds.mysql.x1.2xlarge.2 (16 vCPU, 64GB)
💬 "Which flavor do you want for the RDS instance?"
1. rds.mysql.x1.large.2 — 4 vCPU, 16GB 2. rds.mysql.x1.xlarge.2 — 8 vCPU, 32GB 3. rds.mysql.x1.2xlarge.2 — 16 vCPU, 64GB
👤 "Option 1 — the large one"
💭 "Need a storage_type compatible with MySQL 8.0 in this region."
hcloud_list_rds_storage_types(region="la-north-2", database_name="MySQL", version_name="8.0")
→ ULTRAHIGH
💭 "Need the VPC and subnet to place this database."
hcloud_list_vpcs(region="la-north-2") → ca5aa4ea-4df9-...
hcloud_list_subnets(vpc_id="ca5aa4ea...") → 701ac87c-47ea-...
💭 "All values resolved. Final code:"
resource "huaweicloud_rds_instance" "mysql" {
  name           = "prod-mysql"
  engine         = "mysql"
  engine_version = "8.0"
  flavor_ref     = "rds.mysql.x1.large.2"    ✓
  storage_type   = "ULTRAHIGH"               ✓
  vpc_id         = "ca5aa4ea-4df9-..."         ✓
  subnet_id      = "701ac87c-47ea-..."         ✓
}
You: "Deploy a web server to my existing VPC"
💭 "Let me get the ECS instance schema first."
terraform_get_provider_details(service_slug="compute_instance")
→ needs: image_id, flavor_id, network.uuid, availability_zone...
💭 "Writing with what I know..."
resource "huaweicloud_compute_instance" "web" {
  name              = "web-01"
  image_id          = "???"    ← need Ubuntu image
  flavor_id         = "???"    ← need available flavors
  availability_zone = "???"    ← need AZs in region
  network {
    uuid = "???"              ← need subnet ID
  }
}
💭 "Need an image. What Ubuntu images are available?"
hcloud_list_images(imagetype="gold", os_type="Linux")
→ Ubuntu 22.04: 67c29d17-33bd-... · Ubuntu 20.04: a1b2c3d4-5678-...
💬 "Which OS image should I use?"
1. Ubuntu 22.04 LTS 2. Ubuntu 20.04 LTS
👤 "Ubuntu 22.04"
💭 "Need a flavor and availability zone."
hcloud_list_flavors(region="la-north-2") → c6.large.2, c6.xlarge.2, ...
hcloud_list_availability_zones(region="la-north-2") → la-north-2a, la-north-2b, la-north-2c
💬 "Which flavor and availability zone?"
Flavors: c6.large.2 (2vCPU/4GB), c6.xlarge.2 (4vCPU/8GB) AZs: la-north-2a, la-north-2b, la-north-2c
👤 "c6.large.2 in la-north-2a"
💭 "Need the subnet for the network block."
hcloud_list_vpcs(region="la-north-2") → ca5aa4ea...
hcloud_list_subnets(vpc_id="ca5aa4ea...") → 701ac87c...
💭 "All values resolved. Final code:"
resource "huaweicloud_compute_instance" "web" {
  name              = "web-01"
  image_id          = "67c29d17-33bd-..."       ✓
  flavor_id         = "c6.large.2"              ✓
  availability_zone = "la-north-2a"             ✓
  network {
    uuid = "701ac87c-47ea-..."              ✓
  }
}
You: "The prod API server is down, restart it"
💭 "I need to find the server first."
hcloud_list_servers(region="la-north-2", name="prod-api")
→ server_id: 1a2b3c4d-5e6f-..., status: ACTIVE
💭 "Restarting is an operational action — Terraform can't do this. Using the CLI escape hatch with safety confirmation."
hcloud_cli( 
  command = "ECS BatchRebootServers --cli-region=la-north-2
             --servers.1.id=1a2b3c4d-5e6f-...",
  confirm = true
)
→ ✓ Server reboot initiated successfully
Beyond Terraform

Actions Terraform can't do — HCloud MCP can

Terraform Can't

  • Restart / stop / start servers
  • Resize server flavor (live)
  • Attach / detach volumes
  • Reset server password
  • Create manual RDS backup
  • Restart RDS instance
  • Pause / resume AS groups
  • Execute AS policy manually
  • Attach / detach elastic IPs
  • Modify security group rules
  • Upload OBS objects

HCloud MCP Can

  • ECS BatchRebootServers
  • ECS ResizeServer
  • EVS AttachVolume
  • ECS ResetServerPassword
  • RDS CreateManualBackup
  • RDS StartInstanceRestartAction
  • AS PauseScalingGroup
  • AS ExecuteScalingPolicy
  • EIP AttachEip
  • VPC CreateSecurityGroupRule
  • obs cp

Get Started

Up and running in minutes

1

Install OpenCode

curl -fsSL https://opencode.ai/install | bash
2

Configure MCP Servers

{
  "mcp": {
    "hcloud": {
      "type": "local",
      "command": "hcloud-mcp"
    },
    "terraform": {
      "type": "local",
      "command": "terraform-mcp-server",
      "environment": {
        "TF_API_TOKEN": "..."
      }
    }
  }
}
3

Start Building

# Start OpenCode and ask:
opencode

> Write Terraform for an RDS instance
> List all VPCs in la-north-2
> Restart the prod-api server
